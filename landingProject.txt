این متن را به‌عنوان زمینه پروژه بخوان و کار را روی کد موجود ادامه بده. پروژه را از صفر بازنویسی نکن. ابتدا فایل‌های فعلی را بررسی کن؛ این یادداشت جایگزین واقعیت کد و دیتابیس نیست.

پروژه و هدف
-----------
یک پنل محلی فارسی و راست‌چین برای ساخت لندینگ Hamkadeh داریم؛ متن درخواست و بنر را می‌گیرد، اطلاعات را استخراج می‌کند، امکان اصلاح و بازبینی می‌دهد و با API خود سامانه، تصویر را آپلود و لندینگ را ایجاد می‌کند. ورودی آینده ربات تلگرام است؛ هنوز ربات تلگرام پیاده نشده و منطق ساخت باید مستقل از UI باقی بماند.
پوشه پروژه: D:\Code روی ویندوز، PowerShell.
Backend: TypeScript، Node.js >=24، Express، SQLite داخلی node:sqlite.
Frontend: React، TypeScript، Vite. Playwright برای آداپتر مرورگری و تست‌ها موجود است؛ مسیر اجرایی فعلی عمدتاً HTTP مستقیم است و برای هر ساخت به Chrome باز نیاز ندارد.
نشانی محلی معمول: http://127.0.0.1:3140

شیوه همکاری و محدودیت مهم
------------------------
کاربر فارسی و کوتاه صحبت می‌کند و انتظار اجرای تغییرات را دارد، نه فقط پیشنهاد. از سؤال تأیید غیرضروری پرهیز کن. متن‌های توضیحی اضافه در UI نگذار.
با ابزارها لندینگ واقعی نساز و دکمه نهایی کپی را خودکار نزن، مگر کاربر صریحاً برای همان آزمون اجازه جدید بدهد. تست‌های ساخت را روی mock/fixture انجام بده. اجازه آپلود CDN قبلاً داده شده، اما فایل‌های قدیمی یا عملیات نامشخص را کورکورانه تکرار نکن.
کاربر اجازه نمایش کامل توکن مسیریابی سرپرست/شرکت در پنل محلی را داده است؛ توکن ورود حساب و کوکی‌ها هرگز نباید در UI، لاگ یا پاسخ ابزار نمایش داده شوند.
کاربر قبلاً برای همین پروژه اجازه واردکردن نشست Chrome احراز هویت‌شده همکده/CDN و نگهداری رمزگذاری‌شده آن در بک‌اند داده است. نشست مشاوره مستقل است و از همکده به آن fallback نکن.
این فایل عمداً هیچ مقدار توکن، کوکی یا کلید رمزگذاری ندارد. برای ادامه تنظیمات موجود را حفظ کن.

اجرای برنامه
------------
Open-Panel.vbs: سرور را پنهان در پس‌زمینه اجرا و یک تب Chrome باز می‌کند.
Close-Panel.vbs: فقط فرایند ثبت‌شده همین پروژه را، در نبود عملیات فعال، می‌بندد.
start.cmd: اجرای دستی با خروجی ترمینال.
scripts/panel-launcher.ps1 پارامترهای -NoBrowser، -CheckOnly و -Stop دارد.
data/panel-process.json مشخصات فرایند مدیریت‌شده را نگه می‌دارد؛ PID را ثابت فرض نکن.
فرمان‌های معمول:
  npm.cmd run build
  npm.cmd start
  npm.cmd test
روی این ویندوز npm.cmd را به npm.ps1 ترجیح بده.
ساخت frontend با build به dist می‌رود؛ تغییر backend برای اجرا نیازمند راه‌اندازی مجدد سرور است. قبل از هر توقف، قفل عملیات و صف فعال را بررسی کن. به فرایندهای دیگر Node/Chrome دست نزن.
در جلسات قبل Stop-Process گاهی Access denied یا NullReferenceException داده؛ اگر توقف ضروری بود، مسیر، زمان شروع و PID را با panel-process.json تطبیق بده و تنها همان PID را با مجوز لازم متوقف کن. هرگز taskkill کلی برای node.exe یا chrome.exe نزن.

  rezaei: نام سرپرست رنجبران؛ گروه سایت رنجبران؛ حداقل تایپ 771000

  gheshmi: نام سرپرست مددی؛ گروه سایت مددی؛ حداقل تایپ 7001000
تغییرات گروه رنجبران چند بار رفت‌وبرگشت داشته؛ تصمیم نهایی «رنجبران» برای هر دو نام سرپرست و گروه است، نه مائده رضایی.
آخرین تغییر: قشمی به مددی تبدیل شد و چهار توکن مستقیم، ادوایس، ترند و آرتان برای مددی و پویا با مقادیر تازه کاربر در دیتابیس رمزگذاری و جایگزین شدند. آنها را از پیام‌های قدیمی یا فایل seed دوباره برنگردان.
توکن‌های جدید فقط در تنظیمات رمزگذاری‌شده دیتابیس فعلی ثبت شدند؛ در کد یا این فایل درج نشده‌اند. فایل seed قدیمی ممکن است مقادیر اولیه داشته باشد و برای بازسازی تنظیمات فعلی مرجع معتبر نیست.
شرکت‌ها: adwise=ادوایس، trend=ترند، mostaghim=مستقیم، artan=آرتان. شرکت‌های سفارشی هم قابل افزودن‌اند.
مهاجرت تنظیمات نام‌ها در server/store.ts فعلاً تا settingsVersion=9 است؛ مهاجرت‌های 6، 8 و 9 مربوط به تغییر نام و گروه‌ها هستند. نسخه را بدون بررسی پایین نیاور.

موضوع سناریو دسته‌بندی را مشخص می‌کند؛ ابهام نیازمند انتخاب دستی است.
عنوان: {دسته‌بندی} {تایپ} {نام بلاگر} / {نام سرپرست}

مقادیر اجرایی را از تنظیمات بخوان؛ URLها در کد پراکنده نشوند. دسته‌بندی، تایپ و توکن مستقل‌اند.
هر دسته می‌تواند آدرس اختیاری Moshavere داشته باشد. Hamkadeh پیش‌فرض است. نمونه مشاوره 13550 صرفاً نمونه بوده و نباید بدون تعیین موضوع به دسته‌ای نسبت داده شود. دامنه خروجی مشاوره landing.moshavere.me است؛ نشست مستقل دارد. آزمون واقعی ساخت نهایی مشاوره انجام نشده است.

اسلاگ و تاریخ
-------------
اسلاگ = نام فینگلیش بدون فاصله/کاراکتر نامعتبر + MMDD شمسی؛ سال در اسلاگ نیست.
پیش‌فرض تاریخ امروز تهران است؛ تاریخ موجود در متن درخواست خودکار مبنای اسلاگ نیست.
اکنون تاریخ دلخواه شمسی قابل انتخاب است. در ساخت تکی کنار اسلاگ، ورودی تاریخ و دکمه «اعمال تاریخ» و «امروز» وجود دارد.
در ساخت گروهی تاریخ فقط یک‌بار در هدر و کنار انتخاب سرپرست گرفته می‌شود و روی تمام کارت‌ها اعمال می‌شود؛ انتخاب تاریخ از هر کارت حذف شده است. تاریخ صف در پیش‌نویس مرورگر ذخیره می‌شود و کارت‌های تازه هم از آن استفاده می‌کنند.
تغییر تاریخ فقط چهار رقم آخر را عوض می‌کند و املای دستی نام را نگه می‌دارد. اگر انتهای اسلاگ دستی با تاریخ قبلی مطابقت نداشت، توقف و پیام دقیق؛ بازنویسی خودسرانه نکن. با تغییر تاریخ باید تأیید ساخت قبلی باطل شود.
تاریخ درخواست متادیتا است و خالی بودن آن دیگر مانع ساخت نیست؛ این شرط قبلاً خطای عمومی «نام بلاگر، تاریخ، تصویر و اسلاگ لاتین معتبر لازم است» ایجاد می‌کرد. اکنون اعتبارسنجی نام/بنر/اسلاگ جدا و خطای صف همراه شماره درخواست است.
تبدیل نام‌ها پیشرفته‌تر شده: واژه‌نامه حدود 590 نام کوچک، تفکیک نام/فامیل، نام مرکب، گزینه‌های املایی و هشدار نام ناشناخته داریم. پوریا باید pouria باشد، نه pvria.
ویرایش دستی اسلاگ خودکار بازنویسی نشود. حافظه SQLite املای کامل بلاگر را بدون تاریخ ذخیره می‌کند؛ تاریخ برای درخواست بعدی تازه محاسبه می‌شود. یادگیری عمومی نام کوچک فقط با دکمه صریح کاربر انجام می‌شود.

ساخت گروهی و بازیابی
--------------------
هر کارت متن و بنر مستقل دارد؛ BannerPicker بین حالت تکی و گروهی مشترک است.
سرپرست فقط یک‌بار در هدر انتخاب می‌شود و تمام کارت‌ها برای همان سرپرست هستند. تغییر سرپرست، توکن‌ها و تایپ‌ها را تنظیم و تأیید قبلی را پاک می‌کند.
تایپ شروع در بخش بازبینی اولین کارت وارد می‌شود؛ بقیه به ترتیب و غیرقابل‌ویرایش هستند. شماره تایپ بعدی یا بازه‌ها را بی‌دلیل در صفحه نمایش نده؛ مدیریت شمارنده از تنظیمات حذف شده است.
قبل از اجرای واقعی صف تأیید صریح وجود دارد. اجرا ترتیبی است و با اولین خطا یا نتیجه نامشخص متوقف می‌شود.
هر نتیجه موفق یک دکمه کپی مستقل دارد که هر دو خط را با هم کپی می‌کند:
  https://landing.hamkadeh.com/{slug}
  {type} {blogger}
پیش‌نویس صف شامل فایل‌ها، متن‌ها و ویرایش‌ها در IndexedDB همین مرورگر ذخیره می‌شود تا با رفرش از بین نرود؛ این ذخیره با تاریخچه SQLite فرق دارد و بین مرورگرها مشترک نیست.
در تاریخچه checkbox انتخاب سفارش، انتخاب سفارش‌های آماده و دکمه «بازگرداندن به ساخت گروهی» داریم. فقط review/ready قابل بازیابی‌اند، حداکثر 50 و برای یک سرپرست. سفارش ساخته‌شده، فعال یا نامشخص را نباید دوباره به صف ایجاد برد.
بازیابی از همان job ID و بنر ذخیره‌شده استفاده می‌کند؛ دوباره آپلود لازم نیست. این عمل خودش ساخت را شروع نمی‌کند. تایپ شروع بعد از بازیابی باید بازبینی شود.

تایپ، کنترل تکرار و خطا
----------------------
شمارنده‌ها در SQLite به تفکیک شناسه سرپرست‌اند؛ پس از موفقیت قابل‌اثبات افزایش می‌یابند. شکست/لغو تایپ را مصرف نکند. قفل lease جلوی هم‌زمانی و اجرای تکراری را می‌گیرد.
مصرف محلی شماره تایپ: هشدار + checkbox تأیید استفاده مجدد مجاز است؛ تأیید باید دقیقاً برای همان سرپرست و شماره باشد. سوابق قبلی پاک نشوند.
تکرار واقعی ترکیب type+token در سایت: قانون سخت‌گیرانه مستقل است. فقط شمارش قطعی صفر اجازه کپی می‌دهد. بیشتر از صفر، پیام نامعتبر، شمارش نامعلوم یا Modal ناموجود => توقف؛ این محدودیت دکمه دورزدن ندارد.
بسته‌شدن Modal یا HTTP 200 به‌تنهایی موفقیت نیست؛ نتیجه ساخت باید با شواهد سایت تأیید شود. پس از ارسال نامشخص، uncertain و حفظ قفل؛ هرگز خودکار دوباره کپی نکن. reconcile دستی با شاهد وجود دارد.
خطاهای واقعی سایت بعد از کپی، از جمله اسلاگ تکراری، باید در خروجی نمایش داده شوند و حساسیت‌زدایی شوند.
خطای قطعی و امن امکان اصلاح همان سفارش و تلاش دوباره با همان بنر را دارد؛ image cache رمزگذاری‌شده با اعتبارسنجی GET استفاده می‌شود. برای خطای اسلاگ، بنر دوباره آپلود نشود.
اشکال تطبیق بنر قبلاً با تشخیص MIME/پسوند از امضا و گزارش diagnostic پیگیری شده. لاگ upload فقط اطلاعات امن/هش و شناسه پیگیری دارد، نه نشست، توکن یا بدنه حساس.
در frontend اگر درخواست تغییردهنده به علت CSRF قدیمی با پیام مشخص بازآوری صفحه 403 شود، bootstrap تازه می‌گیرد و یک بار تلاش مجدد می‌کند؛ کاربر مجبور به رفرش و از دست دادن فرم نشود. خطای عمومی را کورکورانه retry نکن.

تنظیمات و ظاهر مورد قبول کاربر
-----------------------------
افزودن توکن یعنی ثبت توکن موجود در برنامه، نه تولید در سایت. افزودن با نام شرکت جدید انجام می‌شود. جایگزینی فقط سرپرست+شرکت دارد و dropdown توکن مورد جایگزین حذف شده. توکن‌های نام‌دار قدیمی هنوز ممکن است وجود داشته باشند؛ آنها را ناخواسته پاک نکن.
پیکربندی پیشرفته عمومی JSON حذف شده؛ فقط مرجع ساخت موضوع‌ها و آدرس اصلی/اختیاری دوم و افزودن مرجع مجاز است.
UI ساده، سبک و شیک با تاکید محدود صورتی/رز و سطوح خنثی؛ کاربر تم سراسر صورتی را نپسندید و نخواست به تم آبی قبلی برگردیم. رنگ را افراطی نکن.
لوگوی اصلی کاربر در public/brand-mark.png است؛ جای حرف «ه» هدر استفاده می‌شود. فونت محلی Estedad variable است؛ فونت پیش‌فرض قدیمی را برنگردان.
توضیحات ثابت اضافه و footer حذف شده‌اند؛ هشدار/خطای واقعی و تأییدهای لازم باقی بمانند.

npm.cmd run build برای TypeScript و bundle؛ npm.cmd test با scripts/run.mjs تست‌ها را esbuild و سپس Node test اجرا می‌کند.
اجرای مستقیم tsx در این محیط یک بار ENOMEM از os.userInfo داده؛ مسیر استاندارد تست esbuild است.
تست‌ها دیتابیس موقت می‌سازند. store را بدون DATA_DIR موقت در اسکریپت آزمایشی import نکن؛ startup آن می‌تواند سفارش‌های اجرایی را uncertain کند.
برای بررسی تنظیمات زنده فقط از API امن یا SQLite read-only استفاده کن؛ تنظیمات را کامل چاپ نکن چون توکن رمزگذاری‌شده/حساس دارد.
تست‌های UI با Edge headless و تمام APIهای mock؛ مرورگرها را بی‌دلیل همزمان اجرا نکن چون حافظه ویندوز گاهی محدود می‌شود.
اسکریپت‌های مفید:
  node scripts/verify-batch-ui.mjs
  node scripts/verify-batch-ui.mjs --restore
  node scripts/verify-batch-ui.mjs --reuse-type
  node scripts/verify-name-ui.mjs
  node scripts/verify-panel-flow.mjs
  node scripts/verify-panel-flow.mjs --retry-flow
  node scripts/verify-panel-flow.mjs --site-error
  node scripts/verify-settings-ui.mjs
  node scripts/verify-upload-error-ui.mjs
  node scripts/verify-ui.mjs
بعضی اسکریپت‌های قدیمی scripts شامل real/probe/upload هستند؛ بدون خواندن محتوایشان و مجوز متناسب اجرا نکن.
آخرین تغییرات هدر تاریخ گروهی با تست‌های mock بازیابی/رفرش و name UI بررسی شده‌اند؛ buildهای تغییر نام‌ها و جایگزینی توکن‌ها هم پاس شدند. ادعا نکن همه گروه‌ها یا توکن‌های جدید با ساخت واقعی تست شده‌اند؛ صرفاً ثبت رمزگذاری‌شده و نگاشتشان بررسی شد.
رشته‌های فارسی را با PowerShell here-string به node pipe نکن مگر encoding را مدیریت کنی؛ قبلاً فارسی به ??? تبدیل شده. برای ویرایش Unicode از apply_patch یا اسکریپت با escapeهای \u استفاده کن.

کاری که از چت بعدی انتظار دارم
----------------------------
این فایل فقط انتقال زمینه است و به‌خودی‌خود دستور ساخت لندینگ یا تغییر برنامه نیست. پس از خواندن، درخواست جدید مرا انجام بده. تنظیمات فعلی، توکن‌های جدید، تاریخچه، کش بنر، املای یادگرفته‌شده و پیش‌نویس‌ها را حفظ کن. قبل از ادعای عملکرد تست‌نشده، محدودیت را شفاف بگو. اگر به پروژه روی دستگاه جدید دسترسی نداری، روشن بگو که این پرامپت شامل خود کد و داده‌های پروژه نیست.
