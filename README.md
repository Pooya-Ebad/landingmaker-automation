برنامه محلی فارسی برای دریافت درخواست و بنر، بازبینی اطلاعات، اجرای مرورگری و نگهداری تاریخچه در SQLite. رابط React از API مستقل استفاده می‌کند؛ اتصال تلگرام به منطق رابط وابسته نیست.

## وضعیت تحویل و آزمون

- ساخت TypeScript و خروجی تولیدی Vite اجرا شده است.
- Parser، فینگلیش، اعتبار URL، قفل تخصیص، جلوگیری از اجرای مجدد، شمارنده، رمزگذاری توکن و بازیابی نتیجه نامشخص آزمون دارند.
- Adapter ساخت با **مرورگر واقعی Edge روی صفحات کنترل‌شده تستی** آزمون دارد: صفر فارسی/عربی، عدد مثبت، پیام مبهم/متناقض و نبود شاهد موفقیت.
- آزمون HTTP شامل آپلود، پیش‌نمایش، تأیید، منع ارسال تکراری، توقف پیش از ساخت، ماسک‌کردن توکن، CSRF و ماندگاری پس از راه‌اندازی مجدد است.
- نمایش دسکتاپ، تنظیمات، تاریخچه و موبایل با Playwright بررسی شده است.
- با Chrome واردشده کاربر، هر چهار URL دسته‌بندی باز شدند؛ یکتابودن فیلدهای عنوان، اسلاگ، پیشرفته، گروه، تصویر، تایپ، توکن و ظرف Modal در هر چهار صفحه تأیید شد. دکمه آپلود CDN هم مشاهده شد.
- **تست کامل ساخت روی حساب واقعی Hamkadeh هنوز انجام نشده است.** آپلود واقعی، متن Modal پس از بررسی و شاهد موفقیت به درخواست و بنر واقعی نیاز دارند.
- نگاشت‌های نامشخص عمداً خالی‌اند. تا تکمیل `uploadResult`، `success` و `successText`، برنامه پیش از آپلود یا ارسال ساخت متوقف می‌شود. مقادیر تأییدنشده به‌عنوان Selector واقعی ادعا نشده‌اند.

## اجرای ویندوز

### استفاده از Chrome واردشده شما

میان‌بر `Google Chrome.lnk` پروژه از Chrome نصب‌شده با `--remote-debugging-port=9222` و پروفایل `C:\chrome-debug` استفاده می‌کند. اتصال به این مرورگر و حضور نشست‌های همکده و CDN بررسی شد. میان‌بر را باز نگه دارید؛ سپس در تنظیمات «استفاده از Chrome آماده» را بزنید. معادل آن در JSON:

```json
{"browser":{"mode":"cdp","cdpEndpoint":"http://127.0.0.1:9222","channel":"chrome","headless":false,"timeout":60000}}
```

برنامه به همان نشست وصل می‌شود و برای عملیات تب خودش را باز می‌کند. هنگام قطع اتصال یا ذخیره تنظیمات، مرورگر و تب‌های قبلی شما بسته نمی‌شوند. این رفتار با مرورگر مستقل آزمایشی تست شده است. اگر Chrome آماده در دسترس نباشد، خطای اتصال نمایش داده می‌شود و برنامه خودکار به پروفایل خالی تغییر نمی‌کند. برای برگشت، `browser.mode` را `persistent` قرار دهید.

بازرسی با نشست موجود و بدون ساخت لندینگ: `node scripts/inspect-connected.mjs --pages` . گزارش در `data/inspection` ذخیره می‌شود. نگاشت پیشرفته، گروه و بخش‌های mainPic/type/token از DOM واقعی تأیید شده است؛ فیلدهای هم‌نام در پارامتر دوم وجود دارند، بنابراین انتخاب‌گرها به بخش اول محدود شده‌اند. بخش‌های accordion پیش از تکمیل باز می‌شوند. رفتار نهایی Modal، آپلود واقعی و شاهد موفقیت هنوز به درخواست و بنر واقعی نیاز دارد.

پیش‌نیاز: Node.js نسخه 24 یا جدیدتر، Microsoft Edge نصب‌شده و دسترسی اینترنت به همکده و CDN. نیازی به کامپایل افزونه SQLite نیست؛ از `node:sqlite` استفاده شده است.

در PowerShell:

```powershell
cd D:\Code
npm.cmd ci --cache .npm-cache
npm.cmd run build
npm.cmd start
```

پنل: **http://127.0.0.1:3140** . از همین نشانی استفاده کنید؛ `localhost` به دلیل کنترل Host پذیرفته نمی‌شود. فایل `start.cmd` نیز برنامه را از همین پوشه اجرا می‌کند. برای توقف، در پنجره اجرا Ctrl+C بزنید.

پیش‌فرض مرورگر `msedge` است. در تنظیمات می‌توانید `chrome` یا `chromium` را انتخاب کنید. Edge و Chrome نصب‌شده به دانلود Playwright نیاز ندارند. برای Chromium:

```powershell
npm.cmd run browser:install
```

در محیط توسعه حاضر، دانلود Chromium با پاسخ 403 مربوط به محدودیت منطقه‌ای مواجه شد؛ تست‌های مرورگر با Edge نصب‌شده اجرا شده‌اند.

`npm.cmd run dev` نیز برنامه را اجرا می‌کند. اگر `dist` وجود داشته باشد همان خروجی تولیدی سرو می‌شود؛ پس از تغییر رابط `npm.cmd run build` را اجرا و سرور را دوباره راه‌اندازی کنید. بدون `dist`، Vite به‌صورت middleware اجرا می‌شود.

## گردش کار

**قاعده فعلی اسلاگ:** ماه و روز از تاریخ شمسی روز اجرا در منطقه `Asia/Tehran` گرفته می‌شود، نه تاریخ نوشته‌شده داخل درخواست. تاریخ درخواست همچنان برای سوابق نگه داشته می‌شود. برای نمونه در ۱۴۰۵/۰۸/۱۷، اسلاگ دریا فلورا `daryaflora0817` است، حتی اگر متن درخواست تاریخ ۱۴۰۵/۰۸/۱۶ داشته باشد. اسلاگ دستی پس از ویرایش کاربر خودکار بازنویسی نمی‌شود.

**پارامتر دوم:** پس از تکمیل تصویر اصلی، `selectors.secondaryMainPic` (پیش‌فرض `#collapse20 input[name=mainPic]`) خالی می‌شود و باقی‌ماندن تصویر اصلی دوباره بررسی می‌شود. سایر فیلدهای پارامتر دوم بدون ضرورت تغییر نمی‌کنند.

تحلیل متن، تشخیص سرپرست/شرکت، انتخاب توکن ذخیره‌شده و پیشنهاد اسلاگ در خود backend اجرا می‌شوند و به حضور Codex، ChatGPT یا API مدل زبانی نیاز ندارند. سرپرست اولیه رابط خالی است تا انتخاب پیش‌فرض اشتباه، سرپرست استخراج‌شده از متن را بازنویسی نکند. موارد ناشناخته یا مبهم نیازمند بازبینی دستی‌اند. انتخاب توکن به معنی تولید توکن جدید نیست؛ توکن معتبر ترکیب سرپرست و شرکت از تنظیمات خوانده می‌شود.

اجرای کامل خودکار تا ثبت نهایی همچنان به تکمیل شاهد موفقیت سایت و یک آزمون واقعی مجاز نیاز دارد. در آزمون فعلی فقط تا Modal تأیید پیش رفته‌ایم و دکمه نهایی کپی کلیک نشده است.

1. از «ورود دستی به همکده» مرورگر را باز کنید. نام کاربری و رمز را خودتان وارد کنید. برنامه رمز عبور دریافت یا ذخیره نمی‌کند.
2. در تنظیمات، CDN را نیز باز کنید و در صورت نیاز وارد شوید.
3. نگاشت المان‌های نامشخص را مطابق بخش بعد تکمیل کنید.
4. تصویر JPG/PNG/WebP تا ۱۵ مگابایت و متن درخواست را بدهید و سرپرست را انتخاب کنید.
5. شرکت و دسته‌بندی استخراج‌شده، شماره تایپ و اطلاعات را بازبینی کنید. شرکت یا دسته‌بندی نامشخص خودکار جایگزین نمی‌شود.
6. عنوان و اسلاگ را بررسی کنید. آوانویسی فارسی تقریبی است؛ واژه‌نامه قابل تنظیم است. اسلاگ دستی دیگر خودکار بازنویسی نمی‌شود مگر با «تولید مجدد».
7. «تأیید اطلاعات»، سپس «ساخت لندینگ» را بزنید. اگر تنظیمات پس از تأیید تغییر کند، تأیید دوباره لازم است.
8. وضعیت عملیات و نتیجه را مشاهده کنید. فقط پس از تأیید ساخت، خروجی دوخطی و دکمه‌های کپی نمایش داده می‌شوند.

توکن پیش‌فرض از ترکیب سرپرست/شرکت انتخاب می‌شود. «انتخاب از همه توکن‌های این سرپرست» انتخاب دستی شرکت توکن دیگری را ممکن می‌کند و اختلاف با شرکت درخواست را واضح نشان می‌دهد. توکن سرپرست دیگر قابل انتخاب نیست.

## تنظیم و تأیید Adapter واقعی

در صفحه تنظیمات، JSON قابل ویرایش است. تغییر صفحات، گروه‌ها، شرکت‌ها، نام‌های جایگزین Parser، واژه‌نامه، دامنه‌ها و نشست به تغییر کد اصلی نیاز ندارد.

| تنظیم | کاربرد |
|---|---|
| `landingPages` | URL مستقل چهار دسته؛ HTTPS، میزبان همکده، مسیر کپی و متمایزبودن صفحات بررسی می‌شود |
| `selectors.advanced` | Selector یکتای select مربوط به لندینگ پیشرفته؛ مقدار انتخابی حتماً `1` |
| `selectors.groupLabel` | نام دسترس‌پذیر فیلد گروه؛ گزینه با role و متن دقیق انتخاب می‌شود |
| `selectors.modal` | Modal قابل مشاهده تأیید؛ پیش‌فرض `[role=dialog]` و نیازمند تأیید واقعی |
| `selectors.uploadButton` | دکمه بازکردن File Chooser؛ پیش‌فرض `#upload-button` |
| `selectors.uploadResult` | المان یکتای لینک خروجی؛ input value، anchor href یا متن خالص URL |
| `selectors.success` | المان پیام موفقیت تازه‌ای که فقط پس از ایجاد کپی ظاهر می‌شود |
| `selectors.successText` | متن واقعی شاهد موفقیت، نه متن حدس‌زده |
| `selectors.extraFields` | نگاشت Selector به مقدار مشخص برای ملزومات اضافی |

Uploader فایل را از File Chooser می‌دهد و منتظر تغییر خروجی می‌ماند. URL را از سرویس می‌خواند و پاسخ موفق از همان دامنه با Content-Type تصویر می‌خواهد. اگر CDN به تعامل دیگری نیاز دارد، فقط `HamkadehUpload` باید اصلاح شود؛ هیچ URLای از نام فایل حدس زده نمی‌شود.

Builder پس از ورود به URL دقیق دسته، داده‌ها را وارد می‌کند، فیلدهای اجباری HTML را بررسی می‌کند و «ایجاد کپی» را می‌زند. شمارش از **متن یک Modal یکتا** استخراج می‌شود. فقط عدد صفر مجاز است؛ دکمه «کپی» فقط در همان Modal انتخاب می‌شود. شمارش بلافاصله پیش از کلیک دوباره خوانده می‌شود. نبود Modal یا شمارش، عدد مثبت و پیام متناقض همگی متوقف می‌شوند. دکمه دورزدن وجود ندارد.

تأیید خودکار موفقیت سخت‌گیرانه است: پیام موفقیت تازه و صفحه عمومی موفق در URL دقیق اسلاگ که شماره تایپ و توکن همان درخواست در HTML آن قابل مشاهده باشد. اگر سایت داده‌ها را به روش دیگری ارائه می‌کند، باید در Adapter شاهد معادل قابل اعتماد پیاده شود؛ صرف وجود صفحه عمومی یا بسته‌شدن Modal پذیرفته نیست. در این حالت نتیجه نامشخص می‌ماند و نباید کورکورانه ساخت را تکرار کرد.

بررسی بدون ورود، بدون ایجاد هیچ لندینگ:

```powershell
npm.cmd run inspect:site
```

گزارش metadata المان‌ها و screenshot در `data/inspection` ذخیره می‌شود؛ نتیجه این دستور بدون نشست، تأیید عملکرد حساب واقعی نیست.

## آزمون پذیرش حساب واقعی

با بنر و درخواست واقعی تأییدشده اجرا شود:

- ورود دستی، مشاهده هر چهار صفحه کپی و تطبیق دسته‌بندی هر صفحه با URL تنظیمات.
- ثبت Selectorهای پیشرفته، گروه، Modal، خروجی CDN و شاهد موفقیت از DOM واقعی؛ بررسی ملزومات اضافی، حتی فیلدهایی که HTML required ندارند.
- آپلود واقعی، دریافت URL برگشتی و تطبیق تصویر.
- درخواست با ترکیب تایپ/توکن موجود: Modal باید تعداد مثبت بدهد؛ هیچ کپی نباید ارسال شود؛ لینک مشاهده و هشدار ثبت شوند؛ شمارنده ثابت بماند.
- درخواست با ترکیب جدید: فقط صفر اجازه ساخت بدهد؛ اسلاگ و عنوان واردشده عین پیش‌نمایش، شماره type و توکن صحیح و گروه متناظر باشند.
- موفقیت تازه و لینک نهایی را با داده سفارش تطبیق دهید؛ شمارنده فقط یک بار افزایش یابد.
- خروج و ورود مجدد برنامه: تاریخچه و شماره بعدی حفظ شوند.
- نشست منقضی، قطع شبکه، Modal مفقود/نامعتبر و قطع پس از ارسال: نتیجه موفق ساختگی نمایش داده نشود.

هیچ لندینگ آزمایشی روی سایت واقعی در تست‌های خودکار repository ساخته نمی‌شود.

## شمارنده، هم‌زمانی و نتیجه نامشخص

SQLite با WAL و تراکنش `BEGIN IMMEDIATE` قفل سراسری ایجاد می‌کند. در نسخه اول، عملیات ساخت **سریالی** است؛ درخواست دوم حین اجرای اول پذیرفته نمی‌شود. این تصمیم از تخصیص یک شماره به دو سفارش جلوگیری می‌کند، بدون اینکه شماره ناموفق مصرف شود.

فقط تراکنش موفق، شماره را در `used_types` ثبت می‌کند، شمارنده را افزایش می‌دهد و تاریخچه را موفق می‌کند. شماره بعدی را می‌توان در تنظیمات تغییر داد؛ بازگشت به شماره‌های مصرف‌شده ممنوع است. لغو پیش از اجرا فوری است؛ حین آپلود/تکمیل فرم، در اولین نقطه امن و پیش از ارسال نهایی اعمال می‌شود. پس از ورود به مرحله ارسال نهایی، لغو مجاز نیست چون نتیجه ممکن است در سایت ثبت شده باشد.

اگر ارسال انجام شده ولی موفقیت تأیید نشده، یا برنامه وسط اجرا بسته شود، وضعیت `uncertain` و قفل ماندگار می‌ماند. از تاریخچه سفارش را باز کنید، با اطلاعات همان سفارش در سایت بررسی کنید و نتیجه همراه شواهد را ثبت کنید. «ساخت تأیید شد» شمارنده را یک بار افزایش می‌دهد؛ «عدم ساخت تأیید شد» شماره را حفظ می‌کند. این قابلیت فقط ثبت نتیجه بررسی دستی است و هیچ کپی جدیدی ارسال نمی‌کند. سفارش اجراشده دوباره اجرا نمی‌شود؛ برای تلاش جدید پس از عدم ساخت، سفارش تازه بسازید.

## API برای تلگرام یا منابع دیگر

سرور فقط روی loopback گوش می‌دهد. برای اتصال آینده، bot کنار همین backend اجرا شود؛ برای انتشار شبکه‌ای، درگاه احراز هویت و HTTPS لازم است. `HAMKADEH_API_KEY` اختیاری را به‌صورت متغیر محیطی تعیین کنید و از `Authorization: Bearer ...` استفاده کنید. کلید در فرانت‌اند قرار نمی‌گیرد. درخواست‌های نوشتن پنل از CSRF token دریافتی از `/api/bootstrap` استفاده می‌کنند.

| مسیر | ورودی / خروجی |
|---|---|
| `POST /api/uploads` | multipart با فیلد `image`؛ خروجی `id` تصویر |
| `POST /api/landing/preview` | `{raw, uploadId, supervisor}`؛ خروجی سفارش و داده استخراج‌شده |
| `POST /api/landing/slug` | `{blogger,date}`؛ پیشنهاد اسلاگ |
| `POST /api/landing/approve` | `{id,data}`؛ ذخیره اصلاحات و آماده‌سازی سفارش |
| `POST /api/landing/build` | `{id}`؛ پاسخ 202، شروع اجرا؛ id یک سفارش فقط یک بار اجرا می‌شود |
| `GET /api/landing/jobs` | فیلتر `q,status,supervisor,date`؛ حداکثر ۱۰۰۰ سفارش اخیر |
| `GET /api/landing/jobs/:id` | وضعیت، اطلاعات و نتیجه ماسک‌شده |
| `POST /api/landing/jobs/:id/cancel` | لغو امن پیش از ارسال نهایی |
| `POST /api/landing/jobs/:id/reconcile` | `{outcome: "created" یا "not-created",note}`؛ ثبت بررسی دستی |
| `GET /api/settings` | تنظیمات بدون توکن خام، گزینه‌های ماسک‌شده و شماره بعدی |
| `PUT /api/settings` | `{config,nextType,tokenUpdates:[{supervisor,company,value}]}` |
| `POST /api/browser/login` | بازکردن مرورگر ورود دستی |
| `POST /api/browser/cdn` | بازکردن CDN برای ورود/بررسی دستی |

فیلتر تاریخ از روز میلادی `YYYY-MM-DD` در منطقه `Asia/Tehran` استفاده می‌کند. زمان تاریخچه در رابط فارسی و تقویم شمسی نمایش داده می‌شود.

Bot فقط بنر و متن را به API می‌دهد؛ مسیر preview → اصلاح/تأیید → build → دریافت وضعیت را دنبال می‌کند. Parser، تولید اسلاگ و مدیریت شمارنده در bot تکرار نمی‌شوند. فایل روی سیستم مسیر مستقیم از API دریافت نمی‌کند؛ فقط uploadId صادرشده مجاز است.

## ساختار پروژه

```text
server/core.ts       Parser، نرمال‌سازی فارسی، فینگلیش، کنترل شمارش و URL
server/store.ts      SQLite، رمزگذاری AES-256-GCM، وضعیت‌ها و شمارنده
server/jobs.ts       تأیید، قفل، اجرای مستقل، لغو و تطبیق نتیجه
server/adapters.ts   قراردادها و Adapterهای CDN و Landing Builder
server/browser.ts   نشست مرورگر محلی
server/index.ts      API و سرو رابط
web/                رابط فارسی RTL
config/defaults.json تنظیمات اولیه بدون توکن خام
tests/              آزمون هسته، مرورگر کنترل‌شده، API و پایگاه داده
scripts/            ساخت، اجرا، بازرسی سایت و بررسی رابط
```

اطلاعاتی که در سایت فیلد ندارند، متن خام و کلیدهای ناشناخته Parser داخل سفارش باقی می‌مانند. افزودن alias به Parser از تنظیمات ممکن است؛ برای قالب‌های کاملاً متفاوت می‌توان پیاده‌سازی `parseRequest` را مستقل تغییر داد.

## نگهداری داده و توکن

`data/app.sqlite` تاریخچه و شمارنده، `data/secret.key` کلید رمزگذاری، `data/browser-profile` نشست و `data/uploads` بنرها را نگه می‌دارند. از کل پوشه data هنگام خاموش‌بودن برنامه نسخه پشتیبان تهیه کنید. بدون کلید، توکن‌های رمزگذاری‌شده قابل بازیابی نیستند. نشست مرورگر حاوی cookie معتبر است؛ آن را منتشر نکنید. فایل‌های data، seed توکن، build و node_modules در gitignore هستند. خروجی قابل انتشار فرانت‌اند فقط `dist` است.

توکن‌های داده‌شده در `config/tokens.seed.json` مستقل از منطق قرار گرفته‌اند. در اولین اجرا وارد دیتابیس و رمزگذاری می‌شوند. این فایل خصوصی و خارج از git است؛ نسخه حاوی اطلاعات واقعی را منتشر نکنید. اگر seed همراه نسخه جدید نبود، توکن‌ها را از تنظیمات وارد کنید. تغییرات بعدی از پنل ذخیره می‌شوند؛ ویرایش seed پس از اولین اجرا تنظیمات را بازنویسی نمی‌کند.

رمزگذاری دیتابیس از خواندن مستقیم توکن جلوگیری می‌کند؛ کلید محلی کنار داده‌هاست و جایگزین مجوزهای NTFS حساب ویندوز نیست. در سیستم اشتراکی، دسترسی پوشه پروژه/data و seed را به حساب خودتان محدود کنید. توکن خام در API خواندن، UI و لاگ برنامه چاپ نمی‌شود. توکن استفاده‌شده هر سفارش جداگانه به‌صورت رمزگذاری‌شده برای تاریخچه حفظ می‌شود.

## تست و عیب‌یابی

### آزمون امن نمونه دریا فلورا

`npm.cmd run test:sandbox` متن `tests/fixtures/darya-request.txt` و بنر محلی `#دریا_فلورا (14).jpg` را در مرورگر مستقل بدون نشست کاربری و دیتابیس جدید زیر `data/sandbox` بررسی می‌کند. به Chrome متصل‌شده روی 9222 وصل نمی‌شود. تمام درخواست‌های صفحات مرورگر با fixture محلی پاسخ داده می‌شوند و درخواست ناشناخته مسدود است؛ بررسی HTTP تصویر نیز پاسخ محلی تزریق‌شده دارد. هیچ API تولیدی یا سرویس واقعی آپلود فراخوانی نمی‌شود.

این آزمون مسیر واقعی Job Manager و Adapterها را با پاسخ‌های شبیه‌سازی‌شده اجرا می‌کند: خطای آپلود، ترکیب تکراری، پیام نامشخص و موفقیت شبیه‌سازی‌شده با عدد صفر. شمارنده 771111 فقط در دیتابیس آزمایشی است. شمارنده اصلی پیش و پس از آزمون به‌صورت فقط‌خواندنی مقایسه می‌شود. گزارش HTML/JSON و screenshot ماسک‌شده کنار دیتابیس آزمایشی تولید می‌شوند. وضعیت succeeded در این گزارش صرفاً نتیجه شبیه‌ساز است و به معنای ساخت واقعی نیست.

نام «مشکلات زناشویی» از alias مستقل دسته، سطرهای سرپرست/تایپ بدون دونقطه از aliasهای Parser و فینگلیش دریا/فلورا از واژه‌نامه تنظیمات اولیه خوانده می‌شوند. تایپ ذکرشده در متن به نام `requestedType` حفظ می‌شود؛ متن درخواست به‌تنهایی شمارنده اصلی را تغییر نمی‌دهد. در نصب‌های موجود می‌توان aliasهای جدید و واژه‌نامه را از تنظیمات اضافه کرد؛ آزمون امن تنظیمات نصب موجود را بازنویسی نمی‌کند.

```powershell
npm.cmd run build
npm.cmd test
node scripts/verify-ui.mjs
```

دستور آخر به سرور فعال در پورت 3140 نیاز دارد؛ screenshotها در `data/qa` قرار می‌گیرند. تست HTTP دیتابیس موقت جدا و پورت 3149 دارد. تست مرورگر Edge را بدون رابط باز می‌کند؛ برای Chrome متغیر `BROWSER_CHANNEL=chrome` را تنظیم کنید.

اگر npm.ps1 با ExecutionPolicy مسدود شد، از `npm.cmd` استفاده کنید؛ تغییر سیاست ویندوز لازم نیست. اگر مسیر cache پیش‌فرض اجازه نوشتن نداشت، `--cache .npm-cache` بدهید. هنگام `uncertain` قفل را با حذف دیتابیس یا جدول آزاد نکنید؛ روند بررسی دستی را انجام دهید.
